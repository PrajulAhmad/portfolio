// ARCHITECTURAL PILLARS

How I think about engineering and design decisions.

I believe software resilience is defined by how edge cases, offline conditions, and data boundaries are handled.

01 / FINANCIAL INTEGRITY

Integer Paise Precision

In DoodhWala, milk vendors track morning and evening deliveries with varying fat/SNF rates. Storing invoice totals in IEEE-754 floats introduces fractional rounding errors across months. I strictly model currency as integer paise (1 INR = 100 paise), making calculation drift mathematically impossible.

Constraint: Zero financial discrepancy
02 / LOCAL-FIRST PERSISTENCE

Resilient Offline Synchronization

Network connectivity drops constantly on field delivery routes. Rather than failing or blocking users, mutations write directly to local embedded SQLite. Upon reconnection, an idempotency queue reconciles state against Supabase using UUID keys, soft deletes, and timestamp-based reconciliation.

State Machine: Draft → Queued → Locked
03 / LOW-LEVEL OBSERVABILITY

Kernel /proc Direct Telemetry

When building system monitoring utilities in C, relying on bulky external monitoring agents defeats the purpose. By parsing Linux's virtual /proc/stat and /proc/meminfo directly in C, I extract per-PID CPU jiffies, memory saturation, and process trees with near-zero runtime overhead.

Platform: POSIX · Native Linux C
